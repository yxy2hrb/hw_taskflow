### 新增 Section / 新 UI 区块规则

当修改需求中出现 “新增一个 section / 增加一块新的内容区域 / add another section /
add a new content block / generate another structured block / insert a new part” 等描述时，
你必须严格遵守以下规则：

1. 新区块（Section）的定义
   新区块指一段独立的、包含多个相关元素的 UI 结构，例如：
   - 一组元素组成的内容区（如一段文本区域、一组组件、一段说明、一块示例代码、一组条目）
   - 一个上下文一致的 DOM 子树
   - 一个与现有结构并列的 UI 区域  
   新区块不是单个元素，而是一个有内部层次结构的“小模块”。

2. 新区块的插入位置
   新区块必须插入在当前页面结构同层级的**末尾位置**，
   即在现有兄弟区域的“下方”，保证文档结构连续、稳定。
   若页面中存在明确的内容分区（如组件开始 / 组件结束注释），
   新区块必须追加在**最外层主要内容区的最后**。

3. 新区块内容的结构化输出
   若需求仅提供“内容类型”（如文本、按钮、标题、示例、列表等），
   你必须根据语义生成合理、结构清晰的 DOM 层次。
   示例：
   - 若需求是“一个新说明区”，则包含标题 + 段落。
   - 若需求是“一个新的功能区域”，则包含标题 + 子元素容器。
   - 若需求是“新增一个编号元素列表”，则生成统一结构的若干条目。
   总之：新增区块必须具备**内部结构一致、元素类型合理**的特征。

4. 新区块的内容生成
   若需求不提供具体内容（如文本内容、条目名称等），
   你必须生成**合理的示例文本**或占位内容，使结构完整而不含空白元素。

浮层必须作为 目标控件所在内容区域的共同父容器 的子元素出现，而不是挂在单个按钮的小容器上。

这个父容器要设为 position: relative;，浮层使用 position: absolute; top: 100%; left: 0; margin-top: 8px;，宽度与该区域保持一致或略小（例如 width: 100%; max-width: 400px;）。

禁止把浮层绝对定位到整个侧栏或页面的边缘，也禁止挂在仅包含图标按钮的狭窄容器上。

浮层应完全可见，尽量避免被祖先容器的 overflow: hidden 裁剪；如有需要，可以将浮层放在一个 overflow: visible 的更外层容器中。


===========================================================

若需要图片占位，可在Pexels或者Pixabay寻找相关图片，挑选图片需专业，并符合html内容。禁止预留空白占位或无效占位。禁止凭空捏造图片名称，可以复用原始html中的图片。
若需要使用图标，可使用Lucide Icons中的SVG图标，禁止使用空白或无效占位。
若需要文字占位，需要自行生成占位文字，而不是使用placeholder。比如说，文档内需要文字和图片，则需要自行选择与原html相关的文字和图片。
【按钮尺寸安全规则】
当按钮宽度或高度被指定为固定值，禁止使用会导致内容宽度变成 0 的 padding 组合。
   - 例如 width:32px 禁止与 padding:0 16px 或任意会造成内容宽度 < 图标宽度的组合同时出现。

【弹窗 / 浮层 放置的唯一合法规则】

- 绝对禁止作为任何已有节点的子节点或兄弟节点
- 绝对禁止插入到存在 overflow、transform、position: absolute 的容器中

- inset: 0
- z-index >= 9999
- 内部再用一个子容器控制弹窗大小（而不是靠父节点裁切）
