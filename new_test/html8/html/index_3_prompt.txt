- 编辑时应优先通过注释定位修改区域，避免误伤其它部分。
- 页面中大量区域通过中文注释标记（例如“区域开始”，“组件开始”等）。

  不要在语义不匹配的区域里做修改。

### 新增 Section / 新 UI 区块规则

当修改需求中出现 “新增一个 section / 增加一块新的内容区域 / add another section /
add a new content block / generate another structured block / insert a new part” 等描述时，
你必须严格遵守以下规则：

1. 新区块（Section）的定义
   新区块指一段独立的、包含多个相关元素的 UI 结构，例如：
   - 一组元素组成的内容区（如一段文本区域、一组组件、一段说明、一块示例代码、一组条目）
   - 一个上下文一致的 DOM 子树
   - 一个与现有结构并列的 UI 区域  
   新区块不是单个元素，而是一个有内部层次结构的“小模块”。

2. 新区块的插入位置
   新区块必须插入在当前页面结构同层级的**末尾位置**，
   即在现有兄弟区域的“下方”，保证文档结构连续、稳定。
   若页面中存在明确的内容分区（如组件开始 / 组件结束注释），
   新区块必须追加在**最外层主要内容区的最后**。

3. 新区块内容的结构化输出
   若需求仅提供“内容类型”（如文本、按钮、标题、示例、列表等），
   你必须根据语义生成合理、结构清晰的 DOM 层次。
   示例：
   - 若需求是“一个新说明区”，则包含标题 + 段落。
   - 若需求是“一个新的功能区域”，则包含标题 + 子元素容器。
   - 若需求是“新增一个编号元素列表”，则生成统一结构的若干条目。
   总之：新增区块必须具备**内部结构一致、元素类型合理**的特征。

4. 新区块的内容生成
   若需求不提供具体内容（如文本内容、条目名称等），
   你必须生成**合理的示例文本**或占位内容，使结构完整而不含空白元素。

### 重复元素场景下的唯一锚点规则

页面中经常会有多个内容完全一样的元素，例如：
- 多个 “Get Started” 按钮
- 多个一样的价格标签
- 多个相同文案的 badge 或链接

在这种情况下，你在 [OLD] 中 **绝对禁止** 只写这一行元素本身。  
否则补丁会错误地命中第一个位置。

当存在多个相同元素时，你必须：

1. 在 [OLD] 中额外包含能够唯一定位该元素的上下文：
   - 同一卡片 / 区块的标题文本（例如 “Pro”）
   - 或者包含该元素的父容器的一部分
   - 或者与该元素同一区域内的其他文本

2. [OLD] 必须至少包含 **多行代码**，而不是只有一个标签。
   如果 [OLD] 只有一行且是高度通用的片段，则视为不符合规范。

#### 错误示例（页面中有多个 “Get Started” 按钮时严禁这样写）：

[OLD]
    <button class="cta-button">Get Started</button>
[NEW]
    <button class="cta-button" style="...">Get Started</button>

[OLD]
    <h3 class="plan-title">Pro</h3>
    ...

[NEW]
    <h3 class="plan-title">Pro</h3>
    ...
    <button class="cta-button" style="background: linear-gradient(to right, #e94ebd, #b74de5);">Get Started</button>

2. 如果模型生成了 top > 200px，必须自动改写为合法写法，不允许保留原值。
3. 覆盖层需使用z-index从而浮在最上层。

自动检查！若弹窗使用了style=“top: 1020px; ”则为错误！任何 top不可以大于200px

#### 错误代码示例（Bad Case）：
<div style="position: absolute; top: 1020px; ...">

【弹窗 / 浮层 放置的唯一合法规则】

任何 弹窗 / 浮层 / overlay / 结束卡片 / 弹出面板
一律只允许 插入为 body 的 最后一个直接子元素
新增到 body 末尾时，[OLD] 必须逐字包含 body 内现有的 <script>...</script>，新节点只能插在 <script> 之前，禁止省略或压缩原文结构。

❌ 绝对禁止：
- 绝对禁止插入到任何现有容器内部（包括视频区域、frame、group、card、任何 div）
- 绝对禁止作为任何已有节点的子节点或兄弟节点
- 绝对禁止插入到存在 overflow、transform、position: absolute 的容器中

若需求语义为“局部弹窗 / 浮层 / 结束卡片”：
- 仍然插在 body 末尾
- 仅通过 尺寸（width / max-width / height / max-height） 和 内边距 表达“局部”
- 不通过父容器限制范围

所有弹窗根节点 必须：
- position: fixed
- inset: 0
- z-index >= 9999
- 内部再用一个子容器控制弹窗大小（而不是靠父节点裁切）

如果模型生成的 overlay 不是 body 的最后一个子元素：
- 视为错误输出
- 必须在同一轮输出中修正

该 UI 仅用于视觉呈现，不可交互。
